# Intent Contracts

Intent contract 描述「這次要做什麼、做到什麼程度算完成」，是交給 agent 執行的任務規格。ADR 記錄「為什麼這樣設計」，intent 記錄「這一輪要交付什麼」。

| 編號 | 標題 | 狀態 | 依賴 |
|---|---|---|---|
| [001](001-repo-and-content-model.md) | Repo 骨架與內容資料模型 | 完成 | — |
| [002](002-pipeline-mvp.md) | 內容生產線 MVP（RSS） | 可執行 | 001 |
| [003](003-web-mvp.md) | 前端網站 MVP | **阻塞**：等 ADR-0007 拍板 | 001 |

## 狀態定義

- **可執行**：agent 可以開始。
- **阻塞**：有前置決策或依賴未完成，agent 不得開始。
- **完成**：驗收條件全部通過，人類已確認。

## Agent 執行規則

1. 開始前讀完本 intent、它引用的所有 ADR、以及 `AGENTS.md`。
2. 只做「範圍內」的事。看到範圍外但值得做的事，寫在交付說明的「後續建議」，不要動手。
3. 遇到「需要停下來問」列出的情況，或發現 intent 與 ADR 互相矛盾，停下來說明，不要自行假設。
4. 每一條驗收條件都要能對應到一個自動化檢查；交付時列出每條驗收條件與對應的檢查。
5. 完成的定義：`npm run verify` 通過，且所有驗收條件滿足。

## 範本

```markdown
# NNN. 標題

- 狀態：
- 依賴：
- 相關 ADR：

## 意圖
一兩句話：這次做完，世界有什麼不同。

## 範圍內
## 範圍外
## 不變條件（任何時候都必須成立）
## 驗收條件（每條對應一個自動化檢查）
## 需要停下來問的情況
## 交付時要提供
```
