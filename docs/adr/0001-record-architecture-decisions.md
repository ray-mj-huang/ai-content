# 0001. 使用 ADR 記錄架構決策

- 狀態：已採納
- 日期：2026-10-22

## 背景

本專案主要由 coding agent（Claude Code）在人類監督下實作。Agent 每次啟動都沒有先前對話的記憶，若決策只存在於聊天紀錄裡，agent 會重新推導、做出不一致的選擇，或推翻已經討論過的事。

## 決策

- 所有影響架構、技術選型、資料格式、內容政策的決策，都寫成 ADR 放在 `docs/adr/`。
- 「要做什麼、做到什麼程度算完成」寫成 intent contract 放在 `docs/intents/`，並引用相關 ADR。
- Agent 開始任何任務前，必須讀 `docs/adr/README.md` 與該任務對應的 intent contract。
- Agent 不得自行把 ADR 從「提議中」改為「已採納」，也不得修改已採納 ADR 的內容。發現既有決策不合理時，停下來向人類說明，必要時草擬一份新的「提議中」ADR。

## 後果

- 決策有單一可信來源，agent 與人類讀同一份規格。
- 每個重大改變多一份文件的成本，但換來可追溯性。

## 考慮過的替代方案

- **全部寫在 AGENTS.md／CLAUDE.md**：會變成越來越長、互相矛盾的指令堆，且看不出決策的理由與演變。這兩個檔案只放「如何在這個 repo 工作」的操作說明，並指向本資料夾。
- **寫一份完整 PRD**：對單人專案太重，且不容易對應到可驗證的完成條件。
