# 0008. 篩選與搜尋在前端執行，建置時產生索引

- 狀態：已採納
- 日期：2026-10-22

## 背景

網站是純靜態（ADR-0004、ADR-0007），沒有後端可以處理搜尋與篩選。文章量在可預見的未來為數百到數千篇。

## 決策

- **篩選**：建置時輸出一份精簡的文章索引 JSON（標題、slug、日期、人物、分類、標籤、精選、摘要前幾句），前端載入後在瀏覽器內篩選。條件可組合：分類、標籤（多選）、人物、精選、日期範圍。
- **搜尋**：建置時產生全文搜尋索引，前端查詢。候選工具：Pagefind（專為靜態站設計、索引分片載入）或 FlexSearch。由 `apps/web` 的 intent 實作時選定，並需支援中文。
- 篩選與搜尋條件寫入 URL query string（ADR-0007），重新整理或分享連結時狀態不遺失。
- 分類頁、標籤頁、人物頁仍是**預先產生的靜態頁**，讓搜尋引擎能收錄；前端篩選是在這些頁面之上的互動增強。
- JavaScript 失效時，列表頁仍要能顯示預先渲染的內容（漸進增強）。

## 後果

- 不需要搜尋服務，零營運成本。
- 文章量超過數萬篇時，索引檔可能過大，屆時再評估外部搜尋服務（新 ADR）。

## 考慮過的替代方案

- **Algolia 等託管搜尋**：體驗佳但有成本與外部依賴。未採用。
